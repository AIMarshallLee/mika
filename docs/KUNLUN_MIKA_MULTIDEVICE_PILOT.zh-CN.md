# 昆仑增长｜Mika 多安卓手机执行试点 V1.0

状态：**待设备接入／待真机验收**。本文件只是试点执行手册；它本身不代表已安装、已上线或自动调度已经开发完成。

## 目标与判定

先选 **3 台闲置安卓测试手机**，让每台独立运行 Mika，通过 Mac CLI 逐台发出一个**只读任务**。完成后统计成功率、需要人工干预的次数、耗时、模型 API 成本、结果证据完整度；只有验收通过，再考虑自动批量派单和写入 CRM。不要一次性接入所有旧手机。

- 手机要求：操作 App 至少 Android 12，推荐 Android 14+；只做聊天/网页/文件 Android 11+；Linux 沙箱需 arm64。需能稳定供电、联网，禁止未经测试长期无人值守。
- 每台都需要单独安装并初始化 Mika、模型配置、手机操作权限；每部手机的运行结果与任务记录彼此独立。
- Mac 可从 ADB 多设备列表查序列号，用 `mika --device SERIAL ...` 指定目标；**Mika 原项目没有被证实具备跨手机的统一派单、去重、集中报表系统**，不要把单机 CLI 能力误认为生产级机群调度器。
- 如需要脱离电脑运行：每台手机可以分别用自身 Mika 工作；集中远程调度应在测试后设计可信网络和鉴权，不向公网暴露服务。
- 官方原始使用指南：[首次部署与验收](KUNLUN_MIKA_QUICKSTART.zh-CN.md) · [电脑连接](computer.md) · [CLI](cli.md) · [MCP](mcp.md) · [安全说明](disclaimer.md)。

## 第一批试点岗位与可直接发送的任务

以下任务均是**公开信息只读研究**，不登录陌生账号、不私信、不发布、不删除、不修改设置、不下载通讯录、无需联系任何人。若遇验证码、授权或付费页面立即暂停并报告。

### A01 商机研究

> 在公开网页中找出淮北地区最近可核实的 5 条企业招聘/业务扩张线索，优先家装、家居、制造、电商、营销。每条列：企业名称、招聘岗位或增长信号、为什么可能需要 AI 服务、公开证据 URL、信息日期、是否需人工复核。不允许虚构公司或没有链接的岗位；不登录、不私信、不提交表单，仅输出报告。

### A02 内容研究

> 在公开可访问的网页/内容页面中，观察 5 个「企业 AI 落地、门店获客、家装营销」相关内容案例。每条记录原页面 URL、主题、内容结构、可借鉴的原创选题方向和需进一步验证的信息。不要搬运原文、不要点赞/评论/关注/私信/发布，仅输出分析。

### A03 资料研究

> 只从可公开访问的网页中，搜集 5 个适合淮北企业 AI 服务走访的商协会、产业园区或企业服务机构，记录机构名称、官网或公开入口、公开联系方式（如有）、AI 培训或企业服务相关证据 URL、可接触价值以及需要核验的部分。不得提交表单、拨电话、发送消息或推断私人电话号码，仅输出清单。

这些是**试点任务**，不是已经执行的事实。要扩展到真实客户系统，先完成数据授权、脱敏与最小权限评估。

## 连接与逐台验证（Mac）

环境：Mac 上已安装 `adb` 和 Mika CLI，且 3 台手机已通过 USB 数据线授权调试；先按[首次部署指南](KUNLUN_MIKA_QUICKSTART.zh-CN.md)逐台安装。多手机可使用带独立供电的 USB Hub，但先确认稳定性。

```bash
adb devices
mika devices --json

# 将下面 A01_SERIAL / A02_SERIAL / A03_SERIAL 换成实际 adb 设备序列号
mika connect --device A01_SERIAL --json
mika doctor --device A01_SERIAL --json
mika connect --device A02_SERIAL --json
mika doctor --device A02_SERIAL --json
mika connect --device A03_SERIAL --json
mika doctor --device A03_SERIAL --json
```

通过连接检查后，在每台手机先跑[首次部署指南](KUNLUN_MIKA_QUICKSTART.zh-CN.md)里的 T01–T03。然后依次把上述任务原文分别放进三个本地 UTF-8 文本文件 `a01.txt`、`a02.txt`、`a03.txt`，调用：

```bash
mika --device A01_SERIAL task run --goal-file a01.txt --json
mika --device A02_SERIAL task run --goal-file a02.txt --json
mika --device A03_SERIAL task run --goal-file a03.txt --json
```

各命令返回独立 `task_id`。对每台用对应序列号与任务 ID 查询（不要串台）：

```bash
mika --device A01_SERIAL task wait TASK_ID_01 --timeout 45 --json
mika --device A02_SERIAL task wait TASK_ID_02 --timeout 45 --json
mika --device A03_SERIAL task wait TASK_ID_03 --timeout 45 --json
```

`wait` 有时间上限，超时返回当前状态，不是失败；不要因没有即时结果就重复提交同一任务。直到出现 `done` / `failed` / `cancelled` 等最终状态，再人工检查 5 条证据链接与准确性。**不要在正式任务没有核验前开启无限循环。**

## 试点验收表

| 项目 | 标准 |
|---|---|
| 设备定位 | 3 台 `SERIAL` 与实际手机一一对应，无串机 |
| 连接 | 3 台分别通过连接诊断；不把诊断当作任务成功 |
| 任务 | 各至少成功完成 1 条真实任务，得到终态 |
| 质量 | 每部手机 5 条结果中，至少 4 条有有效来源且信息可人工核实 |
| 安全 | 0 次未经批准的发布、私信、删除、消费及客户数据读取 |
| 成本 | 记录每次任务所用模型与粗略费用，不做无法核实的收益承诺 |
| 记录 | 能找到设备、任务 ID、状态、证据和人工复核结论 |

**通过后下一步**：将证据完整的结果汇总进入既有商机管理表；先人工审核并去重，后续才考虑加入调度控制台。对于多部手机长期运行，需要另做故障隔离、权限管理、断线恢复及任务分发，不能仅靠 Fork 完成。

## 重要风险

1. Mika 的默认「询问模式」并不等于所有写操作都要先问：部分发送、发布、删除可能直接执行。**只读任务+测试账号+人工监督**是试点的控制边界。
2. 多账号批量触达、模仿真人操作、规避平台风控等存在封号、合规及数据隐私风险，本试点不运行此类动作。
3. 无线调试、ADB 和远程 MCP 都是高权限通道。优先 USB；网络接入只用可信局域网或私有 VPN；关闭不再使用的远程访问。
4. 这套部署和设备执行仍**未在用户真实设备上完成**。每步的「已完成」必须来自实际命令回执和机主核验。
